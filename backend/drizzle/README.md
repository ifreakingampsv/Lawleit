# Migrations

Generated by `npm run db:generate` (drizzle-kit, reads `src/db/schema.ts` into
SQL files here), applied by `npm run db:migrate` (`src/db/migrate.ts`, tracked
in the `drizzle.__drizzle_migrations` table). No hand edits to generated SQL —
change the schema in `src/db/schema.ts` and regenerate.

`meta/_journal.json` started empty; migration `0000_dry_raider.sql` (ticket 07)
created the first tables — `firms`, `users`, `sessions`,
`password_reset_tokens`.

## Baseline table conventions (from the first migration onward)

Every tenant table:

- **`id uuid primary key default gen_random_uuid()`** — DB-side default because
  `gen_random_uuid()` is built into Postgres ≥ 13 (no extension, keeps the
  database portable per ADR-0002) and the column stays open to app-supplied
  UUIDs later.
- **`firm_id uuid not null` + index** — the tenant key per ADR-0003; every
  service query filters on it, so the index is not optional. Add the FK to
  `firms(id)` once ticket 07 creates that table.
- **Money is `bigint`, never float or numeric** — amounts are integer paise
  end to end (`app/src/lib/data/types.ts`), and integer arithmetic cannot
  round; `int4` would overflow at ₹2.1 crore, `bigint` will not.
- **`created_at timestamptz not null default now()`** and
  **`updated_at timestamptz not null default now()`** — UTC instants, matching
  the API contract's ISO strings; the application sets `updated_at` on every
  write (no triggers — plain, portable, visible SQL).
- **`deleted_at timestamptz null`** — soft delete; live rows have `NULL`.
  Service queries must filter `deleted_at IS NULL`, and unique constraints
  must be partial (`WHERE deleted_at IS NULL`) so a deleted row's unique value
  can be reused.

Naming: snake_case, plural table names, singular column names — drizzle's
default casing is camelCase, so every column gets an explicit snake_case name.

Never use Supabase-specific features (RLS-as-logic, Supabase auth tables,
`auth.uid()`): ADR-0002 keeps the database a plain, movable Postgres.
