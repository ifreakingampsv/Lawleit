## What was implemented

### 1. First real test suite (was: zero frontend tests)

- Added `vitest` + `jsdom` (devDeps), `npm run test` / `test:watch`, and
  `app/vitest.config.ts` (jsdom, `@/` alias, `app/tests/**`).
- **`app/tests/mockAdapter.test.ts`** (unit): locks the default-mode business logic —
  auth gate ("Not signed in" before login), demo-login fallback, case number
  assignment (`2026-XXXX`), 404→null mapping, inclusive calendar range filter, the
  invoice payment roll-up (partial→sent, full→paid, partially-paid draft stays draft),
  the trust ledger's running `balanceAfter`, lead conversion (linked contact + case,
  activity entry, double-conversion rejection), notifications read-all, and
  localStorage persistence across an "app reload".
- **`app/tests/httpAdapter.contract.test.ts`** (contract): spawns
  `backend/server.mjs` on a random port with a scratch DB, then drives the REAL
  `httpAdapter` — token storage, token-stripped session shape, ApiError statuses
  (401/404/409), 404→null mapping, and the server-side responsibilities (number
  assignment, roll-up, trust ledger, conversion). **Owner handoff built in:** set
  `VITE_API_BASE_URL` to any server claiming the contract and the same suite
  certifies it — no bundled server is spawned when that env var is set.
- Result: **20/20 tests green**.

### 2. Two mock↔server parity bugs fixed (found by writing the tests)

The mock adapter had drifted from the reference backend's contract behavior:

- `recordPayment` with `trustAccount: true` appended **no** trust-ledger entry on the
  mock (the server does). Fixed: same description format and running `balanceAfter`.
- `convertLead` on an already-converted lead silently converted again on the mock
  (the server returns 409). Fixed: mock now throws "Lead already converted".

Both adapters now behave identically for these flows; the tests pin that parity.

### 3. `npm run smoke:api` is now zero-setup

`backend/smoke.mjs` self-spawns the reference backend on a random scratch-DB
(`os.tmpdir`) when nothing is listening on `SMOKE_BASE`, waits for `/health`, runs the
55 assertions, and reaps the child at exit (`spawned.unref()` + exit hook — without
`unref()` the live child deadlocked the parent at exit). The classic two-terminal
flow still works unchanged. Verified: `exit=0`, 55/55, no leftover processes.
