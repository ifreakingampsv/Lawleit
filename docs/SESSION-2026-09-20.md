## Part B — backend fill-in (no owner input required)

Goal per instruction: fill in every backend piece that can be finished without

### B1. `app/src/lib/data/httpAdapter.ts` — stub → full REST client

**Before:** a skeleton — `login`/`signup`/`logout`/`updateFirm`/`updateUser`
threw "not implemented"; every other method was an untyped `http(...) as never`
cast with no error handling; no auth token handling.
**After:** complete implementation of all 40 methods of `LawleitApi`:

- Fully typed against the domain models (no `as never`), 1:1 with the endpoint
  mapping in API_CONTRACT.md.
- `ApiError` class carrying the HTTP status + server error message; JSON error
  bodies are parsed into readable messages.
- Session-token handling: `login`/`signup` store the token
  (`sessionStorage["lawleit.auth.token"]`), every request sends
  `Authorization: Bearer` + `credentials: "include"` so cookie-based backends
  work too; `logout` clears it; `getSession` returns `null` on 401 (app gates to
  login) and rethrows real network/server failures.
- `getCase`/`getContact`/`getInvoice` map 404 → `null` per the API contract
  (`Promise<X | null>`).
- Query-string support (`listEvents` from/to, `listCases` status/q); 204 →
  `undefined`; absolute `VITE_API_BASE_URL` (cross-origin) supported — this was
  actually a bug in the skeleton (`url.pathname` dropped the origin), fixed by
  fetching the full URL object.

### B2. `backend/server.mjs` — new: reference backend (the big piece)

**Before:** nothing — the only runnable backend was the in-browser mock; "http
mode" existed as a TODO stub that could never work.
**After:** a dependency-free Node ≥ 24 HTTP server implementing
[API_CONTRACT.md](./API_CONTRACT.md) 1:1 (58 routes):

- **Storage:** single JSON file (`backend/data/db.json`, path overridable via
  `LAWLEIT_DB`), loaded on boot, written atomically (tmp + rename) on every
  mutation; `--reset` reseeds from scratch.
- **Seed data:** imported directly from `app/src/lib/data/seed.ts` (Node 24
  type-stripping) — the same source of truth the mock adapter uses, so mock and
  HTTP modes demo identically.
- **Auth:** `POST /auth/login` / `signup` return `{ token, user, firm, users }`
  and set an httpOnly cookie; all other routes require the cookie or Bearer
  token; `logout` revokes. **Demo-grade on purpose** (any non-empty password,
  unknown email → first seeded user) — parity with the mock, loudly documented
  in the file header and README.
- **Server-side responsibilities from the contract:** case numbers `2026-XXXX`,
  invoice numbers `INV-XXXX`, invoice status roll-up on payments (paid when
  Σpayments ≥ total), trust ledger with per-client running `balanceAfter`,
  lead-conversion transaction (creates contact + numbered case, marks lead,
  appends activity, 409 on double-convert), trial-end stamping on signup.
- **Ops:** request log line per call (`HH:MM:SS METHOD /path STATUS ms`),
  `GET /health`, CORS (origin-reflect + credentials) so it works proxied
  (`/api/v1` prefix stripped) or direct, body limit 1 MB, graceful JSON errors.

### B3. `backend/smoke.mjs` — new: 55-assertion smoke suite

Covers every endpoint group plus the server-side responsibilities: auth
lifecycle (login → session → logout → 401), CRUD for cases/contacts/events/
tasks/time-entries/expenses/documents/threads/leads, invoice number assignment,
partial-then-full payment roll-up (sent → paid), trust ledger `balanceAfter`,
lead conversion shape (`{lead, contact, case}` + linkage + double-convert 409),
notifications read-marking, 401 for anonymous access. Exits 1 with a failure
list on any assertion miss; doubles as the owner's reference test.

### B4. Adapter switching — `app/src/lib/data/index.ts` + `app/.env.example`

**Before:** adapter chosen by editing source (`export const api = mockAdapter`)
with a comment telling the owner to hand-edit for go-live.
**After:** env-driven — `VITE_API_MODE=mock|http` (default `mock`), plus an
exported `apiMode` for diagnostics. New `app/.env.example` documents
`VITE_API_MODE`, `VITE_API_BASE_URL` (dev-proxy / cross-origin / production
values) and the dev-only `VITE_API_PROXY_TARGET`.

### B5. Dev wiring — vite proxy, npm scripts, combined runner

- `app/vite.config.ts` (**before:** no proxy) → **after:** optional
  `server.proxy["/api"]` when `VITE_API_PROXY_TARGET` is set, so http mode runs
  same-origin (no CORS) in dev.
- `app/package.json` scripts added: `dev:api` (backend only), `dev:http`
  (backend + vite together), `smoke:api` (smoke suite).
- `app/scripts/dev-all.mjs` (**new**): spawns backend (:8787) + vite (:3000)
  with `VITE_API_MODE=http` set automatically, prefixes output by process
  (`[api]` / `[web]`), tears both down on Ctrl-C, appends everything to
  `logs/dev.log` (gitignored).

### B6. Housekeeping

- Root `.gitignore`: added `backend/data/` (runtime DB) and `logs/` (dev logs).
- `docs/logs/` (**new**): committed verification evidence (see Part C).
