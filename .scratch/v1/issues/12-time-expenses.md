## Comments

- (agent, post-build) Surfaces per the contract, nothing more: `GET/POST /time-entries`, `PATCH/DELETE /time-entries/:id` and the expenses twins — the contract defines NO timer route, so timer "start/stop" is exactly what the app does (AppShell.toggleTimer): a purely client-side clock whose stop is one `POST /time-entries` carrying `{minutes, description, billable, date}`. Everything the stop call omits lands on the reference defaults server-side: `caseId` → the firm's NEWEST LIVE case (the reference's `db.cases[0]`, its store being newest-first), `userId` → the firm's first user, `rate` → 300000 paise/hr, `date` → today, `minutes` → 0, `billable` → true.
- (agent, post-build) Amount policy — a deliberate audit delta from the brief: the brief said "amount computation minutes/60*rate, server-side, exact rounding". There is no such computation in the contract, the reference backend, or the mock adapter to mirror: the contract's `TimeEntry` carries `minutes` + `rate` only (no amount), and `(minutes / 60) × rate` is derived CLIENT-side (TimePage/CaseDetail reducers). So `time_entries` has NO amount column and the server computes/rounds nothing — `minutes` and `rate` are stored verbatim as integers (rate = integer paise/hr), and integer paise cannot round. `expenses.amount` IS a real column (bigint integer paise) supplied by the client (the UI converts rupees via rupeesToPaise) and stored verbatim — the smoke posts `amount: 55` and reads it back unchanged. `rate` default is 300000 paise (₹3000/hr, the mock adapter's default); the reference's `300` is its dollar-scale legacy — mock parity wins.
- (agent, post-build) Required caseId: the ticket-11 optional case-link 400 pattern extended to a required variant — create with omitted/""/null caseId defaults to the newest live case (400 "Case not found" when the firm has no live case); unknown, cross-firm, soft-deleted and non-uuid ids are 400s ("Case not found" / "Invalid case id"); patch may re-point the link (existence-checked) but never clear it. `case_id` is NOT NULL + FK + indexed on both tables; `user_id` is an FK-less soft link (cases.lead_attorney_id / tasks.assignee_id pattern).
- (agent, post-build) `invoiced` is server-managed end to end (the events.`source` treatment): column default false, stamped false on create, whitelisted out of create AND patch payloads — a client sending `invoiced: true` gets it silently stripped and false back. The reference gates NOTHING on `invoiced` (Object.assign / filter), so invoiced entries remain patchable and deletable here too; only ticket 13's invoice flow writes the flag, through the service seam (a raw `update time_entries set invoiced = true` in the DB twin proves the column flips without client access).
- (agent, post-build) Parity spot checklist — UI action vs mock adapter, verified in-memory (route tests bind the in-memory repos): timer stop → POST minutes 25 → entry on today's date, newest case, first user, ₹3000/hr default rate, invoiced false, appears FIRST in the list (newest first, both sides unshift); PATCH persistence — only sent fields move, whole entity echoed (mock Object.assign); DELETE → 204, leaves the list, repeat delete 404s; empty POST body lands on every default (zero-minute entry, ₹0 "other" expense). Expenses category vocabulary (filing/travel/copies/expert/other) is the contract's, enforced as a 400 server-side the mock never had. Cross-firm ids are 404s that leak nothing; every member manages both surfaces (practice data, no owner gate — like contacts/events/tasks, unlike /users).
- (agent, post-build) Suites: routes 22/22 (11 time + 11 expenses, in-memory), DB twins `services/time/service.db.test.ts` + `services/expenses/service.db.test.ts` (5 + 5, `skipIf(!DATABASE_URL)` — THE real parity pass once the owner's Postgres exists; truncate lists already include both tables). All eight pre-existing truncate lists extended. Migration `drizzle/0004_wide_post.sql` (+ snapshot + journal) creates both tables: uuid PKs, `firm_id`/`case_id` FKs + btree indexes, `user_id`, `date date` (mode:string — the contract carries ISO days), `minutes int`, `rate`/`amount bigint` (paise), `invoiced bool default false`, `created_at`/`updated_at` timestamptz, `deleted_at`. Full backend suite 137 passed / 43 skipped (DB twins) / 0 failed; typecheck + build green; app 44/44 and smoke 55/55 (SMOKE_BASE on :8799) untouched and green.
- (agent, post-build) For ticket 13 (invoices): there is NO unbilled/uninvoiced query surface yet — the repository seam exposes only `listByFirm`/`findById`, and `ApiTimeEntry`/`ApiExpense` carry `invoiced` for the UI to filter client-side (same as the mock). When the invoice flow needs "unbilled time + expenses for a case", add a selector to the seams (e.g. `listUninvoicedByCase(firmId, caseId)`), implement it in both `drizzle.ts` bindings (`and(eq(...caseId), eq(...invoiced, false), live...)`), and cover it in the DB twins. The flip-side write is already designed: `TimeEntryPatch`/`ExpensePatch` deliberately exclude `invoiced` — ticket 13 should mark entries invoiced through its own service seam (or a dedicated `markInvoiced(firmId, ids)` on these repositories), not via the client-facing patch. Invoice line math uses `quantity × rate` with time lines' quantity in HOURS (`minutes / 60`, the UI's derived-value rule) — keep it in paise end to end.
