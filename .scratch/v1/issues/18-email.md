# 18: Transactional email via Resend

**What to build:** The mailer stub becomes real: transactional email (password reset links, user invites) sends via Resend with a small database-backed retry queue for failures. Minimal set only — invoice/reminder email stays V2. Templates are simple, branded, English-first.

**Blocked by:** 07 (Auth — register Firm, login, sessions), 08 (User management).

**Status:** ready-for-agent — **requires owner**: a Resend account + API key (guided step at execution; a verified domain is a launch-time concern, the test sender works for development).

- [x] Password-reset emails send with working links; invite emails send on user creation
- [x] Failed sends retry via the DB-backed queue with backoff; poison messages surfaced in logs
- [x] Provider behind the existing mailer interface (stub swappable by config; tests use the stub)
- [x] No secrets in the repo; key supplied by environment

## Comments

- (agent, post-build) Seam: the Mailer interface is KEPT (no EmailService refactor) — the ticket-18 binding `OutboxMailer` (`backend/src/services/email/mailer.ts`) implements it as write-to-outbox + drain immediately, so AuthService/UserService call sites, routes wiring, and all CapturingMailer tests are untouched. One additive envelope field, optional `firmId` (the informational outbox soft link), compiles every existing Mailer implementation unchanged. Stateless boots (no DATABASE_URL) keep the plain ConsoleMailer; an explicitly bound `deps.mailer` (tests) always wins — the same optional-binding pattern as storage.
- (agent, post-build) Outbox: `email_outbox` (migration `0010_watery_kingpin.sql`, generated via `db:generate`): uuid pk, `firm_id` NULLABLE soft link no-FK (outbox is operational data addressed by recipient email; the worker runs without firm context — the link is support/debug only and must never constrain a send), `to_email`/`subject`/`body_text`/`body_html` (nullable), `kind` (reset|invite, the V1 vocabulary), `status` (pending|sent|failed, default pending), `attempts` (default 0), `last_error`, `available_at` timestamptz default now() (the backoff clock), `sent_at` nullable, stamps. NO `deleted_at` — operational data, rows are terminal on send or poison; pruning old terminal rows is maintenance, not a feature. Indexes: `firm_id` (the informational query) and `(status, available_at)` (the worker's only hot path). No secrets: bodies carry the single-use token URL; token hash material stays in password_reset_tokens.
- (agent, post-build) Worker (`services/email/worker.ts`): a plain module — `drainOnce()` takes due pending rows (oldest first, batch 20), attempts each once: success → status sent, attempts+1, sent_at; failure → attempts+1, last_error, `available_at = now + 2^attempts minutes` (capped 60), and after 8 attempts status failed + a loud `POISON …` log line (recipient is waiting on an email the system gave up on — must be unmissable). In-flight guard collapses overlapping drains (interval tick while an immediate drain runs) instead of double-sending; `start()` = immediate drain + 30s setInterval (unref'd), `stop()` clears it — buildApp calls start at boot (a restart drains leftovers) and stop in the onClose sweep that ends the pool. drainOnce NEVER rejects — a dead provider degrades to "logged + queued", never a failed API response (the reset token row already exists; the response must not depend on email reachability).
- (agent, post-build) Sender (`services/email/resend.ts`): dependency-free typed fetch client for Resend `POST https://api.resend.com/emails` (Bearer key, `{ from, to[], subject, text, html? }`) — no SDK (one POST, fully typed here, zero deps; the SDK was not installed and docs were not fetchable). `pickSender(config)`: key set → Resend; unset → console sender that logs the message (the link inside bodyText is the dev handoff — behavior identical to the stub) and still resolves so the row records the send. 10s AbortSignal timeout bounds a hung provider; non-2xx throws with the provider's detail so the retry machinery sees it.
- (agent, post-build) Templates (`services/email/templates.ts`): two pure renderers (reset, invite), simple + branded (Lawleit violet #4B4ACF header shell, CTA button, plain-link fallback), English. Both ride `/reset-password?token=…` (an invite IS the reset machinery — the consume route sets the first password); tokens are percent-encoded into the URL (nothing raw reaches the HTML); expiry rendered as UTC. `APP_BASE_URL` (default http://localhost:5173) is the link base; trailing slashes normalized.
- (agent, post-build) Config: `RESEND_API_KEY` (optional, blank = unset → null), `EMAIL_FROM` (default `Lawleit <onboarding@resend.dev>` — Resend's test sender, delivers only to the account owner's own address), `APP_BASE_URL` (default http://localhost:5173) — carried as `config.email { from, resendApiKey, baseUrl }`. Owner paste-in + verified-domain launch note in `backend/.env.example`; README §Transactional email has the step-by-step. ConsoleMailer's log link now reads APP_BASE_URL too (the undocumented APP_URL spelling is retired).
